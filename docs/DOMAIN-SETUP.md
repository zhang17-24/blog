# 域名与 HTTPS

> 当前状态：`claspmoon.cn` 与 `www.claspmoon.cn` 均已解析到服务器，
> **HTTPS 已启用，证书自动续期**，HTTP 请求 308 跳转到 HTTPS。
>
> 本文记录域名接入过程中真正踩到的坑和判断依据，以及以后换域名 / 加域名时怎么做。

---

## 1. 当前状态

| 项 | 值 |
| --- | --- |
| 站点地址 | `https://claspmoon.cn` |
| 证书 | Let's Encrypt，由 Caddy 自动申请并续期 |
| 覆盖域名 | `claspmoon.cn` + `www.claspmoon.cn`（同一张证书，SAN 含两个域名） |
| HTTP 行为 | `308 Permanent Redirect` → HTTPS |
| 服务器地址 / SSH 信息 | 见 `deploy/deploy.env`（该文件已 gitignore，不入库） |

服务器上的关键配置只有一个环境变量：

```bash
# /opt/blog/.env
SITE_ADDRESS=claspmoon.cn, www.claspmoon.cn
```

`Caddyfile` 里写的是 `{$SITE_ADDRESS::80}`，所以**改这个变量就能切换模式**：

| 情况 | `SITE_ADDRESS` | 效果 |
| --- | --- | --- |
| 还没域名 | `:80` | 纯 HTTP，用 `http://<服务器IP>` 访问 |
| 有域名了 | `blog.example.com` | 自动申请并续期 HTTPS 证书 |
| 主域 + www | `blog.example.com, www.blog.example.com` | 多域名用**逗号分隔** |

不设这个变量会默认用 `:80`，所以忘配也能起来，不会启动失败。

## 2. 为什么国内服务器必须先备案

国内云服务商（腾讯云、阿里云、华为云）都有自动化备案检测系统：

> 若域名未备案且解析到国内服务器 IP，**80/443 端口会被拦截**，
> 请求被跳转到固定提示页，提示需先完成备案。

也就是说，在备案完成前把域名 A 记录指过去，访客看到的不是你的站点，
而是云厂商的备案提示页 —— **比直接用 IP 访问更糟**。

`.cn` 域名由 CNNIC 管理，国内监管对 `.cn` 的备案核查更严格，不建议抱侥幸心理。

## 3. 备案对云资源的要求（参考）

这是备案最容易卡住的地方。腾讯云官方要求（原文摘录）：

> **云服务器（CVM）**：需要先购买腾讯云中国境内有公网 IP 的服务器，
> 计费模式需为**包年包月**，购买包月 3 个月及以上（包含续费）
> 且备案期间剩余有效期需大于（含）1 个月。
>
> **注意**：竞价产品不支持进行备案。按量计费模式的云服务器不支持生成备案授权码。

逐项对照清单：

| 要求 | 说明 |
| --- | --- |
| 中国大陆地域 | 中国香港及境外服务器**无需**备案，也**不能**用于备案 |
| 有公网 IP | 且带宽不能为 0 |
| **计费模式为包年包月** | ⚠️ **按量计费不支持** —— 这是最常见的卡点 |
| 购买时长 ≥ 3 个月 | 不足需先续费 |
| 备案期间剩余有效期 ≥ 1 个月 | 否则备案会失效 |
| 不支持绑定 EIP 备案 | 必须是「免费分配独立公网 IP」 |
| 账号实名类型 | 个人备案需为本人实名，且**与域名所有者一致** |

### 域名侧要求

| 要求 | 说明 |
| --- | --- |
| 域名在有效期内 | — |
| 已完成实名认证满 3 天 | 实名信息需约 3 天同步入库工信部，太早提交会因核验不到而失败 |
| 备案主体 = 域名所有者 | 个人备案：姓名、证件类型、证件号码都要一致 |
| 国家批复的域名后缀 | `.cn` 属于批复后缀 |
| 境内注册商 | 境外注册商注册的域名不能直接备案，需先转入 |

> **个人账号说明**：个人实名账号不能生成备案授权码（那是企业账号的功能），
> 但可以直接用自己名下的服务器备案。个人账号一台服务器最多备案 **5 个**网站/域名。

### 把按量计费转成包年包月

如果服务器是按量计费，在**云服务器控制台**操作：

1. 找到目标实例
2. 列表视图：右侧操作栏 → **更多** → **实例设置** → **按量转包年包月**
   页签视图：右上角 **更多操作** → **实例设置** → **按量转包年包月**
3. 设置**续费时长**（≥ 3 个月，建议直接 1 年）与**自动续费**（建议勾上）
4. 勾选同意规则 → **立即转换** → 完成支付

注意事项：

- 转换会产生一个续费订单，**必须完成支付**计费方式变更才生效
- 转换后**不支持 5 天内无理由退还**
- 未支付前不要对实例做任何变更（改配置 / 重装 / 调带宽），否则订单会失效
- **公网 IP 不变** —— 只改计费模式，不重建实例，SSH、DNS、部署脚本都不受影响

### 备案流程（个人备案）

1. 登录云厂商的 ICP 备案控制台 → 选择**首次备案**
2. 填写主体信息与网站信息
3. 选择备案云资源（刚转成包年包月的实例）
4. 提交初审（约 1–2 个工作日）
5. 初审通过后，用云厂商 App 做人脸核验
6. 提交管局审核（各省不同，一般 **7–20 个工作日**）
7. 收到备案号短信 → 完成

备案期间**不要**把域名解析指向服务器，站点继续用 IP 访问即可。

## 4. 切换到 HTTPS 的步骤

三步，前两步在服务器上，**不需要重新构建站点**：

```bash
# 1. 确认域名 A 记录已指向服务器，且解析生效
dig +short <你的域名>                # 应返回服务器 IP

# 2. 改站点地址
ssh <用户>@<服务器> \
  'cd /opt/blog && sed -i "s|^SITE_ADDRESS=.*|SITE_ADDRESS=<你的域名>, www.<你的域名>|" .env && cat .env'

# 3. 重建容器让新配置生效
ssh <用户>@<服务器> 'cd /opt/blog && docker compose up -d --force-recreate web'
```

看证书申请进度：

```bash
ssh <用户>@<服务器> 'cd /opt/blog && docker compose logs -f web'
```

成功的标志是日志里出现：

```
served key authentication   identifier=...  challenge=http-01
authorization finalized     authz_status=valid
certificate obtained successfully   identifier=...
```

**首次申请需要几秒到几十秒。**

最后别忘了把 `.vitepress/site.ts` 里的 `SITE_URL` 改成 `https://<你的域名>` 并推送，
否则 RSS / sitemap 里的链接还指向旧地址。

### 切换前要确认的两件事

1. **域名已完成 ICP 备案**（国内服务器）
2. **安全组放通 443 端口**

> **怎么判断 443 是被防火墙拦了还是单纯没服务在听？**
> 用「立即拒绝 vs 静默超时」区分：
>
> - `Connection refused`（几十毫秒内返回）→ 数据包**到达了**服务器，
>   被内核主动拒绝 → 说明**防火墙是放通的**，只是没有服务监听
> - `Connection timed out`（几秒无响应）→ 被静默丢弃 → 这才是**被安全组拦截**的特征
>
> 找一个确定不放通的端口做对照组，结论就很明确。

## 5. 常见问题

### 5.1 切换后 IP 访问打不开了

**这是正常现象，不是故障。**

`SITE_ADDRESS` 设成域名后，Caddy 会对所有 HTTP 请求做 308 跳转到 HTTPS，
而证书只签给域名、不包含 IP。所以访问 `http://<服务器IP>` 会被跳到
`https://<服务器IP>`，然后因证书域名不匹配而失败。

想验证「服务本身是否正常」，用带 Host 头的方式绕过：

```bash
curl -sI -H "Host: <你的域名>" http://127.0.0.1/       # 在服务器上执行
curl -sI https://<你的域名>/                            # 从外部执行
```

### 5.2 证书签不下来

按顺序排查：

1. 域名 A 记录是否指向服务器：`dig +short <你的域名>`
2. 服务器能否被外网访问 80 端口（Let's Encrypt 的 HTTP-01 校验走 80）
3. 安全组是否放通 80 与 443
4. 看 Caddy 日志里的具体报错：`docker compose logs web | tail -50`
5. 域名是否被墙 / 是否已完成备案

### 5.3 部署成功但内容没更新

先判断是缓存还是真没部署：

```bash
curl -s https://<你的域名>/ | grep "新内容关键词"
```

- 抓不到 → 部署没生效，检查 CI 日志与服务器文件时间戳
- 抓得到但浏览器没变 → 浏览器缓存，强制刷新（HTML 已设为 `max-age=0, must-revalidate`）

### 5.4 想换域名或再加一个域名

不用重建站点，改一个环境变量即可：

```bash
ssh <用户>@<服务器> \
  'cd /opt/blog && sed -i "s|^SITE_ADDRESS=.*|SITE_ADDRESS=新域名, www.新域名|" .env'
ssh <用户>@<服务器> 'cd /opt/blog && docker compose up -d --force-recreate web'
```

然后改 `site.ts` 的 `SITE_URL` 并推送。**记得先加好新域名的 DNS 解析**，
否则证书申请会失败。
